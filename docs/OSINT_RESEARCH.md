# OSINT 调查 Agent

更新：2026-09-27。调查 Agent 在 Rust 服务内执行，新调查默认联网，也可选择 `mode=local`。默认使用无需密钥的 GDELT 近一个月新闻检索；配置 `OSINT_SEARXNG_URL` 后改用该实例的通用网页检索。文件提取与规则分析不调用模型，原有新闻摘要/翻译保持独立。

## 流程与算法

1. 读取事件中质量排序前 30 篇未静音材料，过滤空正文。保留标题、原文 URL、源报发布时间、抓取时间和全文指纹。
2. 使用现有 Tantivy 站内索引检索最多 60 个候选，再经数据库过滤过期索引、静音来源和本事件材料，返回最多 12 条相关线索。检索词默认事件标题，可手动缩短；输入取最多 12 个字面词项，以 OR 检索。中文沿用现有索引分词，不提供跨语言语义检索。相关材料不自动混入当前事件。
3. 按发布者、规范链接、完整正文指纹关系做传递合并。导出正文限制 12,000 字符，但合并使用完整正文指纹，避免正文前缀相同造成误合并。
4. 对规范化正文的前 4,000 个字母/数字字符生成五字符片段集合；两篇均至少有 80 个不同片段、Jaccard 相似度达到 85% 时标为疑似转载。只作为人工检查线索，不改变已知依赖分组。
5. 缺失发布时间保持空值；源报发布时间超过抓取时间 24 小时的材料提示核对时区、预告日期和元数据。不以抓取时间冒充事件发生时间。
6. 每篇最多抽取 5 条、每条 16–360 字符的完整原文句段，优先更正措辞、检索词命中的句段，其次含数字句段。支持中文句末标点，保留英文小数点。完全相同的片段合并来源 ID，按依赖组计数。只标注阿拉伯数字，未提取到数字不代表没有数量信息。
7. 对抽取片段将数字替换为占位符；句式完全相同、数字序列不同且涉及多篇材料时提示检查统计口径、单位和时间。这可能是正常更新，不做语义冲突判断。
8. 生成包含规则发现、来源引用、片段、时间、过程和局限的 JSON，并事务保存到调查档案。规则分析完成显示 `analyzed`，少于两个已知依赖组显示 `insufficient`，不输出真实/虚假评分。

来源陈述、相同文字和报道数量都不直接等于事实成立。规则无法覆盖改写、跨语言转载、影像鉴伪、实体消歧或细致语义矛盾。站外检索仍受服务能力、来源可达性和预算限制；关键词匹配不等于研究问题已得到语义回答。

## 联网闭环与引用

1. `search` 发现候选，只保留 URL、标题和检索词，不把摘要当证据。第一轮使用界面检索词，来源不足时添加 `official report` / `original source`，数字差异或更正线索触发 `correction clarification`（中文查询使用“更正 澄清”）。限定词由代码生成，不从本地正文、文件或页面指令提取。
2. `open_page` 优先读取尚未出现的发布者，每轮最多尝试两页。只接受成功返回的 UTF-8 HTML/纯文本，拒绝不足 80 个非空白字符的正文；每次最多 1 MiB。原始响应只保留哈希和读取元数据，正文快照随报告保存；需要精确字节存证时仍使用独立“抓取证据”功能。
3. 每轮检查来源覆盖、数字差异、更正线索。最多搜索 3 次、尝试读取 6 页、保留 24 个候选，联网总预算 90 秒（搜索最多 20 秒、单页最多 15 秒）。失败读取计入预算；429/搜索服务失败停止补查，不自动重试放大限流。超时保留已经完成的材料。
4. 达到两个不同依赖组的关键词相关站外正文且未见数字/更正线索时停止扩展；这只是规则停止条件，不是“研究完成”或事实正确的证明。缺失日期、未提取文件、截断正文和未完成语义复核仍保留在 `research.gaps`。无新增材料、搜索/页面/时间预算耗尽和服务不可用有不同 `stop_reason`。
5. `find_in_page` 用字面词项定位完整句段，英文采用词边界；中文沿用连续文本匹配，不做分词、翻译或语义理解。报告统一生成，不拼接多个角色的章节。
6. 每条片段有内容派生的稳定 `F-…` ID，每条来源引用有材料 ID、快照哈希和位置派生的 `E-…` ID。`evidence` 记录 URL、标题、源报/抓取时间、`article_content / document_text / page_content`、原文和 UTF-8 字节范围（左闭右开）。位置对应导出正文，不对应 HTML 字节或 PDF 页码。
7. 保存前逐条检查 ID、材料存在性、正文哈希、原文精确范围、来源元数据和所有引用的对应关系，失败则拒绝保存。`citation_audit.semantic_support=not_checked` 明确表示尚未验证语义蕴含。
8. `research.candidates` 分开记录仅发现、已读、读取失败、重复目标，以及实际引用的证据 ID；`rounds` 保存检索词、理由、结果状态和轮后缺口，`budget` 保存消耗。标题或候选数量不增加证据支撑。

公开页面读取逐跳解析并检查 IP，将通过检查的地址固定到请求，禁用代理与自动重定向；拒绝私网、凭据 URL、超限响应，不发送 Cookie、认证或执行脚本。系统 DNS 全部返回 `198.18.0.0/15` Fake-IP 时，使用固定 `https://1.1.1.1/dns-query` 获取真实 IPv4 地址并再次检查、固定地址；该回退只发送域名，不接收私网结果，也不适用于字面 IP 或 `.local`。`ALLOW_PRIVATE_FETCH` 不改变页面边界。`OSINT_SEARXNG_URL` 是服务端管理员配置的可信搜索服务地址，可以是内网实例，禁止 URL 内凭据/查询/片段且不跟随重定向；需启用 JSON 格式。未配置时不会随机选择公共实例。

参考的是公开架构边界，而非 ChatGPT 生产实现：[OpenAI research_bot](https://github.com/openai/openai-agents-python/tree/main/examples/research_bot) 的计划/检索/统一写作编排、[dzhng/deep-research](https://github.com/dzhng/deep-research/blob/main/src/deep-research.ts) 的有界补查循环；本实现额外绑定片段与来源，并采用规则闭环而非模型自主规划。搜索接口依据 [GDELT DOC 2.0](https://blog.gdeltproject.org/gdelt-doc-2-0-api-debuts/) 和 [SearXNG Search API](https://docs.searxng.org/dev/search_api.html)。

## 网络与存储边界

本地模式只访问数据库和索引；联网模式在冻结本地输入后执行公开搜索和正文读取。界面使用持久任务队列；原同步接口保留两个并发槽位、同事件锁与 120 秒等待预算。有界文本比较放在阻塞线程，取消任务不会强制终止已开始的短 CPU 计算，但过期或取消的执行者不能提交结果。文件提取仅启动固定的本地 Poppler/Tesseract 命令。

“抓取证据”仍是独立的用户动作，直接访问该事件已入库文章的原站 URL，沿用私网/重定向检查与精确字节导出。第三方存档查询已停用；旧请求中的 `include_archive=true` 在任何页面抓取前返回 400。历史记录原样保留。

成功的调查自动入库；失败不写入半份报告，不发布快讯或推送。刷新后恢复最近版本，也可选择历史版本、比较材料新增/未纳入/正文变化。`text_sha256` 对应导出文本；`full_text_sha256` 对应完整规范化正文，不是原始 HTTP 字节哈希。精确字节证明仍使用“抓取证据”导出文件。

## 档案、复核与实体

- 顶部「调查」入口独立于事件列表，支持标题检索、分页、历史版本和原站证据导出。`?radar=investigations&case=<id>&run=<id>` 可直接定位特定版本。
- `0014_osint_casebook.sql` 为历史取证创建档案，移除证据对文章和事件的级联删除。源 ID 保留为出处标识。报告、正文快照、取证、复核与关联均不参与阅读器保留周期清理；暂不提供自动清理或删除档案的接口，容量随调查累积。
- 档案目前按原事件 ID 建立。事件重建后可产生新档案；旧档案仍保留，通过同一实体可建立跨档案线索，并未自动解决稳定事件身份或合并档案。
- 片段与规则发现可标为采纳、驳回、待核查，必须填写理由。复核记录追加保存执行人和时间，不修改原报告；采纳不等于事实成立。
- 人工标注人物、机构、地点，可指定最多 12 个别名或选择已有实体。同名不自动合并。片段须逐字存在于指定版本的材料中，且含该实体名称或别名；别名、类型和名称创建后暂不直接改写，误关联可驳回后重新标注。
- 名称/别名检索扫描已保存的正文快照，每批最多 20 个版本，提供游标继续扫描；本机仅允许一个扫描同时执行。采用不区分大小写的字面匹配，英文使用词边界，中文允许连续文字匹配；不做翻译、语义检索或自动身份消歧。同一材料最多生成一个候选，重复扫描不覆盖已确认/驳回的状态。
- 两个已人工确认的实体可记录有方向的关系及原文依据，支持驳回/重新确认并保留操作历史。关系为人工判断，系统仅验证引文存在，不验证语义蕴含。
- 每份报告保存当时已抓取的相关原站证据 ID、元数据和哈希；后续取证不回写旧报告。调查 JSON 包含正文快照、复核、实体、关系和操作历史，原始响应字节通过对应取证导出单独下载。
- `report_sha256` 对应 Rust `serde_json::Value` 的紧凑排序键序列化（UTF-8）的 SHA-256。报告不通过 API 修改；该哈希是完整性检查，不是签名、可信时间戳或防数据库管理员篡改措施。
- 未加入完整浏览器页面归档、多用户案件权限或自动事实核验。后台任务可恢复；联网补查由原始检索词及固定限定词驱动，尚不提供模型自主规划或语义事实核验。

## 本地文件与后台任务

- 在事件调查或独立档案内上传 PDF、PNG、JPEG、UTF-8 文本，按字节识别类型，不信任文件扩展名或客户端 MIME。原件按档案 SHA-256 去重；同内容重复上传返回原文件与任务，不覆盖原件。
- 单文件 10 MiB，每份档案最多 20 个文件，PDF 最多 20 页，图片最多 2,000 万像素。原件独立保留，下载为 attachment + application/octet-stream + nosniff，不内嵌执行 HTML。
- PDF 逐页提取文字层；不足 30 个非空白字符时栅格化至长边 2,000 像素，调用本地 Tesseract `chi_sim+eng`。图片直接 OCR；不访问识别 API。使用开源本地引擎，自研的是导入、留证、分页提取、调度与调查整合，并非训练新的 OCR 模型。
- 每页保存页码、`pdf_text / ocr / utf8` 方法、最多 30,000 字符、文本哈希与截断标记。原件 SHA-256 与整个提取 JSON 的 `extraction_sha256` 分开保存。空结果、损坏/加密 PDF、超页数、缺工具或语言包均明确失败，原件仍可下载；OCR 可能误识别，必须对照原件复核。
- 后台调查在排队时冻结正文、线索、原站证据引用和已完成提取的文件。后续阅读器清理或新上传不改变本地任务输入；联网材料在执行时读取，拥有各自的抓取时间，重试可能取得新版网页；未完成提取的文件在结果中明确提示未纳入。成功提取后再次调查会纳入文件，即使原事件已清理。
- 文件以带页码标记的正文参与规则分析、实体标注与关系记录，每文件仍受 12,000 字符分析预算限制；完整逐页文字在文件详情保留。所有本地文件按未知同一发布者保守分组，不按文件数量推算来源独立性。历史 `article_id` 字段也可指向报告内的文件材料 UUID。
- `0015_osint_documents_jobs.sql` 新增独立原件/任务表。`serve` 启动单个本地任务 worker，多进程以 `FOR UPDATE SKIP LOCKED` 竞争任务。执行租约 10 分钟，单任务最多 5 分钟，过期运行最多自动接管 3 次；明确的提取/分析错误等待人工重试。
- 调查结果 ID 与任务 ID 相同，结果和完成状态在同一事务提交，并校验运行状态、租约 token 与期限。取消使租约失效，执行中的子进程会被终止；重试使用原输入，完成的任务不能重复提交。同档案同时只允许一个后台调查。
- 本地程序固定为 `pdfinfo`、`pdftotext`、`pdftoppm`、`tesseract`，不接受用户命令或路径。清空子进程环境，仅保留受信任的服务 PATH 和固定语言/线程设置；单进程 40 秒墙钟预算、30 秒 CPU、32 MiB 单文件、2 MiB stdout、64 文件描述符，Linux 额外限制 1 GiB 地址空间。使用私有临时目录并在结束/取消后清理。资源限制不是操作系统级网络沙箱。
- 两份 API Dockerfile 已包含 Poppler、Tesseract 和简体中文/英文语言包。直接运行开发服务时需在受信任的 PATH 安装对应程序与语言数据；程序不会自动下载工具或模型。数据库原件、冻结输入和调查版本暂不自动清理，应纳入自托管容量与备份计划。

引擎调用依据：[Tesseract CLI](https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html)、[Poppler pdftotext](https://manpages.debian.org/bookworm/poppler-utils/pdftotext.1.en.html)、[Poppler pdftoppm](https://manpages.debian.org/testing/poppler-utils/pdftoppm.1.en.html)。

## 接口变化

- `GET /api/v2/osint/tools`：`agent=native-osint-v4`、`network_access=true`、`default_mode=online`、`model_required=false` 和实际搜索提供方。
- `POST /api/v2/events/{id}/osint/research`：`{ "query"?: string, "mode"?: "online" | "local" }`，查询词 1–240 字符；新请求默认为 online。
- 导出格式升级为 `rss-osint-research-v4`，保留 v3 字段，并增加 `mode`、`evidence`、`citation_audit`、`research`。历史 v3 报告按原样读取；无 `mode` 的旧冻结任务保持 local，不会在升级后突然联网。
- 旧 `provider` / `analyze` 参数仍返回 422；新模式不复用旧的专用模型入口。
